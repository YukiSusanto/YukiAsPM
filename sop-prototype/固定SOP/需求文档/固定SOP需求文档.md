# AI触发SOP优化需求文档

版本：v1.26（两周业务模型 W1/W2；分页与跟进回复按原型对齐）  
更新日期：2026-10-19  
适用范围：雪梨英语管理系统 → AI销售 → AI触发SOP、素材库

本表以最新确认需求为准。“新增／优化”相对于原产品MVP；原型图列留空，由产品补充。标注待补充的内容不作为本期已完成功能验收。

| 功能模块 | 需求说明 | 原型图 | 验收标准 |
|---|---|---|---|
| **整体导航**<br>位置：左侧AI销售菜单、顶部栏<br>类型：优化 | ① 保留左侧导航、顶部系统栏和面包屑，支持展开、收起。<br>② AI触发SOP下直接进入消息节点配置，不设置SOP管理页。<br>③ 素材库直属AI销售，与AI触发SOP同级，全局共享。 |  | 点击菜单可进入对应页面；侧栏可折叠，当前页面选中状态正确。 |
| **固定SOP配置**<br>位置：AI触发SOP → 消息节点配置<br>类型：优化 | ① 全局仅维护一套固定SOP，各期自动共用；移除按期新建、复制、删除SOP和绑定期数流程。<br>② 进入模块直接展示时间节点与消息配置，提供保存配置及素材库入口。<br>③ 移除查看期数选择器和顶部独立说明区，仅展示本期数据；“本期·第xx期”和可点击的“本期销售N名”放入左侧期数内时间节点区域。<br>④ 本期由系统确定，暂定每周一北京时间00:00重新匹配下一期并更新数据；关联销售数量可点击查看，具体规则见下方。 |  | 打开即进入配置，无期数选择器；到下一期时数据自动切换，固定节点和话术保持。 |
| **两周业务模型**<br>位置：固定SOP规则范围（时间节点周维度）<br>类型：新增 | ① 固定SOP 只覆盖两周：W1 与 W2，不设 W3 及以后，时间节点不再按更长周期延伸。<br>② W1 定位为“本期销转”：负责本期直播前后的触达与转化。<br>③ W2 定位为“追单上一期”：对上一期未转化客户继续追单。<br>④ 以此类推、逐期循环：每进入新一期，W1／W2 的业务角色沿用同一套固定规则，重新落到该期与其上一期。<br>⑤ 周筛选固定只展示 W1（本期销转）、W2（追单上一期）两档，并直接标注业务含义；新增／编辑时间节点时周数只接受 1–2。 |  | 时间节点周数只能为 1 或 2，无法创建 W3 及以后的节点；周筛选只有 W1、W2 两档且各自显示“本期销转”“追单上一期”；校验失败时给出明确提示。 |
| **本期数据更新规则（暂定）**<br>位置：本期匹配与后台定时更新<br>类型：新增 | ① 每周一北京时间00:00固定触发一次，重新匹配业务系统中的下一期；匹配完成后，该期作为页面展示的本期，不按期数编号直接加1。<br>② 更新该期关联销售、企微客户范围和直播数据；数据更新完成后，按各消息最新筛选条件统一重算一次预计触发人数。<br>③ 每周固定刷新和批量重算一次；业务编辑好友日期、标签等条件时仍按既有规则更新估算。<br>④ 固定SOP规则继续复用；实际发送人数读取新本期对应的执行结果，历史发送记录与人数不改写。<br>⑤ 下一期未配置、匹配／更新失败、重试及补偿规则待补充。本轮仅记录产品规则，不改动现有原型的切期演示逻辑。 |  | 周一00:00匹配下一期并刷新本期数据、重算预计人数；周内不重复周期刷新，历史记录保持。 |
| **固定规则同步生效**<br>位置：时间节点、消息节点配置保存<br>类型：优化 | ① 修改SOP后，所有期数尚未执行的消息使用最新配置，包括修改前已配置／生成但未执行的消息。<br>② 已执行消息保留发送记录，不重发、不改写历史内容与人数。<br>③ 规则配置与各期执行记录分开保存，不能仅更新后续新建任务；实际发送前需读取最新生效配置。<br>④ 业务避开触达时点修改，作为操作注意事项；本期不增加时间已过后的自动补发／跳过逻辑。 |  | 修改保存后，各期未执行消息使用最新规则；已发送记录不变。 |
| **时间节点**<br>位置：SOP配置页左侧<br>类型：优化 | ① “直播阶段”改为“期数内时间节点”，“新增阶段”改为“新增节点”。<br>② 周筛选固定为 W1（本期销转）、W2（追单上一期）两档，仅显示当前周节点，不提供第三周及以后。<br>③ 展示节点名称、W-D编码、消息数、启停开关和编辑入口。<br>④ 新增／编辑保留名称、W-D编码、状态；同一SOP编码不可重复。原型名称上限128字、周数仅1–2、天数1–7。<br>⑤ 外侧直接启停；“•••”提供编辑及红字删除。窄屏用周筛选加节点下拉节省空间，并在消息区提供删除当前时间节点入口。<br>⑥ 删除前确认节点名称与所含消息数量，确认后连同消息配置一并删除，作用于全局固定SOP的未执行消息；已发送记录不改写。删除当前节点后自动选择剩余有效节点，全部删除则显示空态；取消不修改配置。 |  | 可按周新增、编辑、启停及删除节点；周数只接受 1–2（W1 本期销转／W2 追单上一期），填 3 及以上不可保存并提示；取消删除保持原样，确认后节点和消息移除，自动切到有效节点；重复编码不可保存。 |
| **消息节点列表**<br>位置：SOP配置页右侧<br>类型：优化 | ① 显示拖动手柄、时间、发送动作、选中标签、排除标签、话术、预计触发人数、实际发送人数、素材数量及详情／编辑／删除。<br>② 话术最多两行，超出以省略号截断，区域高度不超过两行；完整内容在详情／编辑查看。<br>③ 时间、动作、人数、素材和操作列宽稳定，长话术不挤压其他字段；标签显示且／或标记。<br>④ 每页固定10条，不提供每页条数切换；分页条左侧展示“共N条消息 · 第x/y页”，右侧提供页码与前后翻页。<br>⑤ 支持新增、查看、编辑、删除，保存后同步消息数量。 |  | 可新增、编辑、删除及翻页查看消息；话术不超过两行，各字段不重叠；操作对应正确消息。 |
| **消息展示排序**<br>位置：消息列表左侧拖动手柄<br>类型：新增 | ① 拖动调整当前时间节点内的消息展示顺序，支持方向键上／下辅助调整。<br>② 展示顺序单独保存，分页沿用该顺序。<br>③ 实际发送严格按各消息的配置时间执行，不受展示顺序影响。 |  | 拖动并重新进入后顺序保留；将13:00消息移到14:30后方，不改变其13:00发送时间。 |
| **消息编辑：时间与动作**<br>位置：新增／编辑消息节点上方<br>类型：优化 | ① 支持固定时间及相对直播时间，固定时间结合期数、W-D确定日期。<br>② 相对时间仅保留直播前、直播开始后、直播结束后及分钟数，不再选择直播场次；分别按开始前、开始后、结束后计算。<br>③ 旁边展示对应直播日期、开始及结束时间作为参考；数据缺失明确提示。原型偏移支持0–1440分钟。<br>④ 发送动作保留私信1v1、社群发送，删除全量发送；本期社群发送仅显示规划入口，不可执行。 |  | 可保存固定或相对时间并重新查看；相对时间显示对应参考；不能提交社群任务或非法分钟数。 |
| **发送人群：客户范围与好友日期**<br>位置：消息编辑 → 发送人群上方<br>类型：优化 | ① 基础范围为本期对应销售企微账号下的客户，后续条件均在此范围内筛选。<br>② 添加好友时间只精确到日，使用开始日期“至”结束日期，不选择时分。<br>③ 按业务时区的自然日筛选，包含开始日和结束日全天；不填表示不限，开始日期不可晚于结束日期。<br>④ 旧配置中的好友时间在界面按日期展示。 |  | 可选择日期范围筛选客户；起止日客户均可命中，同一天可选；倒置日期不可保存。 |
| **发送人群：标签规则**<br>位置：好友日期下方<br>类型：优化 | ① “邀约标签／包含标签”统一改为“选中标签”；固定排除、过滤标签统一称“排除标签”。<br>② 两组分别选择满足任一（或）／满足全部（且），默认或，互不影响。<br>③ 选中标签：或＝带任意所选标签即可进入；且＝同时带齐全部标签才进入；不选则不限。<br>④ 排除标签：或＝命中任意标签即排除；且＝同时命中全部标签才排除；不选则不排除。<br>⑤ 先按好友日期限定范围，再应用选中、排除条件；命中排除条件优先剔除。<br>⑥ 保存、刷新、自动切期后保留两组关系，旧数据默认或。 |  | 选A、B后，仅有A与同时有A、B的客户在且／或下得到对应结果；排除条件优先，空标签不误排客户。 |
| **预计触发人数**<br>位置：消息列表、消息编辑及详情<br>类型：新增 | ① 按好友日期、选中标签、排除标签及两组且／或关系估算；编辑区同时展示日期筛选后的基础人数。<br>② 条件变化后更新，系统进入下一期后重新计算；预计人数不等于实际送达数。<br>③ 正式版区分未估算、估算中、N人、0人、失败／重试并展示估算时间；失败不可当作0，旧请求不可覆盖新结果。 |  | 修改筛选条件后人数更新；0人与失败可区分；估算操作不会发送消息。 |
| **实际发送人数**<br>位置：仅消息节点配置列表，预计触发人数右侧<br>类型：新增 | ① 在预计触发人数旁新增实际发送人数，只在该列表展示，不增加到消息编辑或详情。<br>② 读取对应消息的实际发送结果，不使用预计人数替代；暂无结果显示“—”，接口返回0时显示“0人”。<br>③ 实际发送人数按本期及消息分别读取，自动切期后不可沿用上一期结果；具体统计口径与执行接口对接时确认。 |  | 进入消息节点配置可并排查看预计与实际人数；无结果和0人可区分，其他页面不新增此字段。 |
| **往期数据**<br>位置：消息节点配置 → 顶部标题右侧 → 独立页面<br>类型：新增 | ① 在页面顶部主标题“消息节点配置”右侧增加「往期数据」按钮，点击后进入独立的「往期数据」页面（同一工作区内切换，不新开浏览器标签、不新增左侧菜单），页面提供面包屑与「返回消息节点配置」入口。<br>② 页面按时间倒序展示本期之前的已结束期数（如本期为第134期，则依次为第133、132、131…期），采用两级折叠：外层按期数、内层按时间节点（W-D 编码）。<br>③ 两级均默认折叠，进入页面只看到期数摘要行（期数、期数时间、关联销售人数、时间节点与消息条数、实际触发人数），避免一次性展开过长。<br>④ 展开期数后展示该期概览与该期「实际触发人数」，以及该期执行时生效的「当时的模块快照」；再展开某个时间节点，才展示该节点当期的消息明细。<br>⑤ 快照为只读副本，消息明细包含当时的时间、发送动作、选中标签、排除标签、话术内容、素材数量，以及该条消息的实际发送人数；全页不提供新增、编辑、删除入口。<br>⑥ 打开时展示Loading状态；本期之前没有已结束期数、或历史尚未归档时展示“暂无往期数据”空态。<br>⑦ 本期切换后，刚结束的期数自动归档到往期数据；快照冻结该期执行时的配置，之后修改固定SOP不改写历史快照，历史实际发送人数也不与预计触发人数混用。 |  | 标题右侧可看到入口，点击进入独立的往期数据页并可返回配置页；期数与时间节点两级折叠默认均不展开；展开期数可见实际触发人数与只读快照，展开时间节点可见时间、发送动作、话术等核心字段；全页无任何编辑／删除入口；无历史期数时展示明确空态；修改当前配置不影响已归档快照。 |
| **话术编辑与变量**<br>位置：消息节点 → 话术内容<br>类型：优化 | ① 输入、变量、已引用素材及四类素材快捷入口合并为一个编辑模块，统一保存。<br>② 顺序为话术输入、变量快捷插入、已引用素材、底部素材入口。<br>③ 快捷插入只保留直播场次1／2／3；点击后二级显示直播名称、日期、时间、链接，插入对应场次变量。<br>④ 删除客户姓名等快捷入口，保留旧话术中的历史变量，不自动改写原文。<br>⑤ 运营备注单独保留，不作为消息内容发送；消息详情只读。 |  | 可在光标处插入对应直播变量；编辑后一次保存；备注和历史变量不会误混入或丢失。 |
| **真实文案预览**<br>位置：消息节点 → 话术内容<br>类型：新增，待实现 | ① 增加预览实际文案，使用当前未保存话术读取接口数据替换变量。<br>② 支持查看模板与渲染结果；缺失字段或接口失败明确提示，不替换为空、不沿用过期结果。<br>③ 当前原型尚未补齐此入口，直播变量具体接入细节后续完善。 |  | 点击预览可看到替换后的文案；预览不保存、不发送、不改写原模板。 |
| **SOP触发后跟进回复**<br>位置：消息编辑 → 话术下方<br>类型：已移出本期原型，待后续版本 | ① 本轮原型已整体移除跟进回复入口（含开关、规则卡片、打标签选择），消息编辑不再包含该区块。<br>② 业务口径保留：原“回复处理”拟改为“SOP触发后跟进回复”，开关为“是否启用跟进回复”；开启后按规则卡片展示用户回复内容、跟进方式、回复内容，支持添加与删除规则。<br>③ “触发值”改为“用户回复内容”，不改变既有匹配规则；随消息统一保存。<br>④ 打标签的具体操作仍待补充，多选按且关系，独立于发送人群筛选。 |  | 本期不验收跟进回复；原型不展示相关入口。后续版本恢复时按②③④实现。 |
| **消息素材引用**<br>位置：话术模块底部、引用素材库弹窗<br>类型：优化 | ① 提供全部图片、全部视频、全部音频、全部文档入口，打开对应类型素材。<br>② 支持分组、类型、名称筛选及多选；分组选项随类型切换。每页固定5条、不提供每页条数切换，跨页选择保留。<br>③ 确认后展示名称、大小、分组并随消息保存；取消不改变原引用。<br>④ 素材名称仅供内部识别，发送时只发送实际素材，不额外发送名称文字。<br>⑤ 移除引用只影响当前消息，不删除共享素材。 |  | 可按类型分页多选并引用，保存后仍可查看；取消不提交；移除引用不影响其他消息。 |

原型说明：原版复刻及现有交互优化版保留不改；本轮另存“固定SOP版”，使用独立配置存储。该原型验证固定配置及本期数据自动更新，不接入真实任务队列和发送服务；交付HTML的CSS／JS全部内联，无外部运行资源。原型依据演示期数开始日期（北京时间）判断本期；正式版暂按每周一北京时间00:00匹配下一期并统一重算，周期规则见表；本轮仅更新文档，原型仍沿用演示开始日期。期数、销售、直播时间与人数为演示数据，实际发送及正式接口仍需开发。上传文件保存于当前浏览器，不随HTML跨设备迁移。保留四类各24项、共96项分页演示素材；演示占位与真实可用文件须明确区分。往期数据的历史期数、实际触发人数与模块快照均为演示数据：按期数开始日倒推生成，较早各期消息条数更少、发送时间略有差异，用于体现“快照对应当期配置”；正式版需由服务端按各期返回执行结果与配置版本快照，原型在本期切换时会把刚结束的期数冻结归档为只读快照。
